   Quiet-machine H-SI is 955.4 ms vs rung2 798.7 = 1.20x (not the loaded

   +GEM rung the visitor actually ran, so a live page can never show a
   ratio it did not measure.  qa_live_v7.py asserts "7,953" never returns.

2. NEW, and not optional: the hero KPI moved from compile+execute to
   EXECUTE.  With ~8 s of GEM compile a compile+execute hero reads
   4.6 s -> 2.8 s -> 8.8 s -> 8.3 s, i.e. it goes UP at the GEM rung and
   the whole ladder reads backwards.  Card is now "Execute time"; the
   wall-clock total is spelled out directly under it plus a "compile-bound"
   chip on exactly the rungs where compile > execute; the compile number
   itself stays full-size in the bar legend.  Nothing is hidden.

3. NEW: the compile disclosure is ~25 s, not ~9 s.  The ~9 s figure counts
   the compile ONCE, but the certification protocol `-i 1 --warmup` plans
   TWICE (warmup pass + timed pass).  Verified directly on the rung-3
   config: `-i 1` = 15.0 s wall, `-i 1 --warmup` = 24.5 s wall, with the
   REPORTED compile unchanged at ~9.5 s.  Measured through the page over a
   5-cycle soak (medians): base 13.9 s, si 10.2 s, gem 25.2 s, ssrf 24.7 s.
   The run button therefore reads "Compiling plan… ~25 s".

4. NEW (the list above missed these): the toolbar still advertised the v6
   dataset.  Fixed — connchip "ladder-v6" -> "ladder-v7", and the stat
   chips 900K -> 2.7M nodes and 15.6M -> 19.9M edges (450,000 NODE +
   2,250,000 PROFILE; F 9,165,500 + R 172,000 + V 8,325,500 + PROFILE_OF
   2,250,000 = 19,913,000).

5. NEW: the Plan tab was rebuilt, not just relabelled.  All three trees now
   show the HashAgg explicitly ("GROUP BY venue · 172,000 -> 33,452,
   5.1x collapse") with the PROFILE_OF join and the 200-column IdSeek

   below the wide materialization, which is the entire answer to the

   no longer in the aggregating part) and now show the verbatim traced
